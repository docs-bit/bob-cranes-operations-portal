The Problem

VULN Data endpoints fully public

All 4 data endpoints (getBookingSummary, getDocuments, getChatMessages, sendChatMessage) were publicProcedure with no auth check. Anyone who knew a booking ID could read all client data or post chat messages.

VULN Sender spoofing

sendChatMessage accepted sender as user input. An attacker could impersonate any identity when posting messages.

VULN Token generation unprotected

generateMagicLink and generateOtp were unauthenticated. Anyone could mint client portal tokens for any booking.

WEAK Insecure OTP generation

OTP values were generated with Math.random() — not cryptographically secure. An attacker could predict OTP values.
