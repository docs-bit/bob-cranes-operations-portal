💡 Key Architectural Insights

1. Dual Department Code Systems: Two separate department code conventions exist — bookingRules.ts uses short codes (SAL, DOC, LG...) while departmentAccess.ts uses slug codes (sales, documentation, lifting-gears...). The lifecycleNotificationDepartment map in routers.ts bridges them.
2. Shared Rules as Single Source of Truth: The shared/ directory contains 30+ modules with pure functions (no side effects) that both client and server import. This ensures booking stage transitions, RBAC checks, and conflict detection logic are identical on both sides.
3. Monolithic Router Pattern: server/routers.ts (1600+ lines) contains ALL tRPC procedures in a single file. While this works, it's the second-largest community (cohesion 0.11) and could benefit from domain-based splitting.
4. Home.tsx as the Mega-Component: The main workspace view contains 44+ extracted symbols including booking management, crew views, gear selection, attendance, training, and department dashboards. This is the highest-traffic file in the system.
