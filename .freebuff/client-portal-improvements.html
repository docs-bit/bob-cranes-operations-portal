Client Portal Security — Architectural Improvements

4 recommendations from a fresh-eyes review. Each targets a real gap, not theoretical risk.

1 Client Procedure Middleware

HIGH IMPACT Secure by default, not opt-in

Every data endpoint manually calls validateAndScope(). One forgotten call = unauthenticated access. The rest of the app uses tRPC middleware (protectedProcedure) to enforce auth automatically.

Before — Manual per-endpoint

publicProcedure→validateAndScope()→DB query

Each endpoint must remember to call it. 4 do today. The 5th might forget.

After — Middleware enforces automatically

clientProcedure→ctx.clientPayload→DB query

New endpoints secure by default. JWT validated once, payload on context.

Effort

~15 lines of middleware + updating 4 endpoints. Reuses existing requireUser pattern.

Tradeoff

Adds clientProcedure but pattern already exists for protectedProcedure.

2 Rate Limit Verify Endpoints

MEDIUM IMPACT OTP brute-force prevention

verifyOtp is public. Anyone with a booking ID can brute-force the 6-digit OTP (900K possibilities, no rate limit).

Attacker knows booking ID→Brute-force OTP→No rate limit = fast

Fix

Reuse rate limiter from sales.ts. Max 5 attempts per IP per 15 minutes.

Effort

Low — reuse existing pattern. ~10 lines.

Tradeoff

Legitimate mistypes get temporarily locked. 5 attempts / 15 min is generous.

3 Fix TOCTOU Race in Token Verification

SECURITY BUG Duplicate session issuance

db.verifyClientPortalToken does SELECT then UPDATE. Two concurrent requests can both see usedAt=NULL.

Before — Two separate queries

SELECT usedAt→check null→UPDATE usedAt

Race window between SELECT and UPDATE.

After — Atomic single query

UPDATE SET usedAt=NOW()→WHERE usedAt IS NULL→RETURNING *

Single atomic operation. Only one request wins.

Effort

Low — replace 2 queries with 1 in db.ts. 3 lines.

Tradeoff

Changes db.ts but surgical, not a refactor.

4 Filter Client Portal Data

PRD COMPLIANCE Information leakage

getBookingSummary returns the full Booking record. PRD §6.14 says clients should only see relevant info.

FieldCurrentlyShould
lpoReferenceYes (internal)No

Effort

Medium — map Booking to ClientBookingView type.

Tradeoff

Adds a type, but internal vs. external data should never share the same shape.
